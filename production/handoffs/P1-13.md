# P1-13: Bot teammates that walk and do chores

Owner: AI Programmer  Date: 2026-10-07

## Done

`--bots <n>` (doc 05 s3) adds n bot teammates on the host. Doc 05 s19: a bot is a `Player` driven by
a script through the same host paths as a client, so it can be killed and takes part in the trap race.
Doc 01 "Testing > Bot teammates": walk, do chores, can be killed. Playing clips waits for voice clips
(DD Phase 2+), so it is not built.

- A bot is a roster entry with a negative peer id (-1, -2, ...). ENet ids are positive, so they never
  clash. Every peer spawns it as a remote `Player` (roster RPC) and sees it through the host's `moves`
  stream. Clients run no bot code.
- Movement: each physics tick the bot walks its path at `Data.speed(&"walk")` and sends move frames
  (the client packet bytes) into `Players._ingest`. So the speed check, footstep Noise, stillness and
  `player_positions` treat it like a client. `seq` counts send intervals of game time, so
  `--time-scale` never reads as a speed spike. After each frame the bot takes the host's kept
  position, as `apply_teleport` does for a client.
- Routing: `bot_route.gd` holds waypoints for the DD Phase 1 gray box (doc 04 s9). Routes go through
  the barn door, round strip 2's tip (R2) and behind the barn's west wall. Bots have no collision.
- Chores (`bot.gd next_job`, host state only, never other players' positions). Order: at dusk or
  night, repair the generator, or refuel below half a tank (fill the fuel can first). Then sell (bag
  full, or nothing ripe), harvest, plant, then water (fill the can first). Otherwise stroll to an idle
  spot. Bots share a claims table so two bots never take the same target. Holds go through
  `Net.request_received` (`hold` and `hold_cancel`), the signal the RPC emits; the registry validates
  them.
- A bot whose `Game.players[id].ghost` is true stops where it fell.
- `--seed` seeds bot choices.
