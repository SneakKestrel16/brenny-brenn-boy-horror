# P2-18 handoff: version refusal, no sends to refused peers

## Done
1. **`version_mismatch`.** `Net.request_join` checks the version first. If `protocol_version` differs
   from `Net.PROTOCOL_VERSION`, or `build_id` differs from `Game.build_id()`, the host refuses with
   `version_mismatch`. It also logs `net_join_version` (`peer`, `protocol_version`, `build_id`).
   The check runs in the lobby and in a running match. A lobby joiner has already been admitted at
   connect, so `_refuse` removes it from the roster, and the windowed client closes its session
   (`Game.leave_session()`, from P2-17).
   QA hook: the client flag `--protocol-version=<n>` sends `<n>` instead of `PROTOCOL_VERSION`.
   The main menu line is "That farm runs a different version of the game." Doc 06 now marks it
   built in s5 step 3, the s7 table and the s14 command line.
2. **No sends to refused peers.** `Net.send_bytes` now skips any peer in `_refused` or `_pending`,
   and any peer that is not connected. This covers broadcasts (`peer` 0) as well as single
   targets, so every caller is covered (`players.gd:71`, `creature.gd:226`, the voice relay). The
   plain broadcast still runs when nobody is refused or pending.
   Inference: `_pending` peers (a running match, uid not yet known) should get no world state
   either, because they are not players yet. Their `_admit` sends the state they need.
