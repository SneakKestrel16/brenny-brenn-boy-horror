# P5-29 Playtest 2026-10-09 log fixes

## Root cause: Lambda capture freed
`game/voice/clips.gd` `play_packets` (was line ~500): a `create_timer(...).timeout` lambda captured the clip's
`AudioStreamPlayer p` (capture index 0; the `is_instance_valid(p)` guard sits inside the body, too late).
`stop()` / `_drop()` frees `p` before the timer fires (live clips replaced or stopped, `clips_freed`), so Godot
errors when the engine calls the lambda with a freed capture. The client in the log received and played a live clip
every few seconds, matching the error cadence (48 errors, each near `clip_received`/`live_clip_cut`).
Inference: the log has no stack, so the match is by the capture-at-index-0 + clip cadence; other lambdas checked
(`soundscape.gd:445` captures self first and `p` is the emitter itself; player.gd lambdas live as long as the player).

Repro (`logs/p5_29/repro2.gd`, not staged): freeing a node captured by a timer lambda prints the exact
`Lambda capture at index 0 was freed. Passed "null" instead.`; the `.bind(instance_id)` method form prints none.

## Fix
- `clips.gd`: timer now connects `_drop_id.bind(p.get_instance_id())`; `_drop_id` uses `instance_from_id` and drops
  only if alive.
- Lobby READY: `game/ui/lobby.gd` `_on_go` ignores a client toggle within 400 ms of the last (key repeat on the
  focused button fires `pressed`), and host `ui_accept` ignores echo. Host side `game/core/game.gd`
  `on_lobby_ready_request` drops requests under 250 ms apart per peer and requests that do not change state.

## Verification

- `multi.py -n 2 --headless --frames 1800 --bot` host+client on port 54481: MULTI PASS, 0 error lines.
- Repro above: error before pattern, clean with bind.
- Not verified: live key-repeat on the real READY button (needs a human with a window).
