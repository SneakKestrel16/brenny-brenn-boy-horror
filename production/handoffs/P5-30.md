# P5-30 handoff: Net send to disconnecting peers (Q-342); P5-05 message review (D-180)

Owner: Network & Voice Programmer. Status: in review.

## What changed
- `game/net/net.gd` `to_peers`: skips any peer where `_connected(id)` is false, as `send_bytes` already does (P2-18).
  The single `rpc` broadcast now runs only when no peer is refused and every peer is `STATE_CONNECTED`; otherwise the
  per-peer `rpc_id` loop runs. Fixes Q-342: when several clients drop at once, the first leave's `apply_roster` (and the
  `player_left` listeners in `cosmetics.gd` and `debt.gd`) no longer send to the peers still mid-disconnect.
- Gotcha: `multiplayer.get_peers()` returns `PackedInt32Array`, which has no `all()`; it is wrapped in `Array(...)`.

## D-180 verdict: P5-05 messages in net.gd accepted
- `request_cosmetic(op, id, slot)`: `any_peer`, reliable, channel 0, typed `StringName` args, sender from `_sender()`.
  Host validates everything in `Cosmetics._on_request` (ghost, owned, price, store distance, slot in `SLOTS`, unknown
  ops ignored). Wire shape fine.
- `apply_cosmetics(table)`: `authority`, reliable, whole-table resend. Table is small (2 slots per farmhand), fine on
  channel 0.
- Two comment fixes only: `request_cosmetic` now documents the `sync` op and the `apply_refused` answer;
  `apply_cosmetics` gained its missing `##` comment giving the table shape (matches doc 05 cosmetics section).
- Note, not a defect: any client can send `sync`, which rebroadcasts the table to all. Harmless (reliable, tiny, the
  same as the store's resend); no rate limit added.
