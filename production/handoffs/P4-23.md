# P4-23 Menu lobby (Gameplay)

## Done
- The lobby (`game/ui/lobby.tscn`, root now a `Control`) is a menu screen, not the barn. No world, no WorldLook, no player bodies: nobody spawns until the host starts the season, then everyone changes to Main and spawns at the barn spawn markers as before.
- Left column: the P4-09 role cards, clickable with the mouse (the old R-to-cycle is gone: the mouse is free in a menu). Taken roles greyed; all locked with a note when a loaded season keeps its roles (`Game.season_uids`). Cards refresh on `roles_changed` and when a player leaves.
- Right column: roster (name, role, voice setting, READY / not ready), join code, Discord line; Settings: Difficulty (`easy`, `normal`, `nightmare` from `data/difficulty.json`, plus the current one if it is another, e.g. `short_season`) and Streamer-safe. Host edits them through `Game.set_group_settings` (P4-11); clients see them disabled. Buttons: Settings, Leave to menu.
- Ready: a client's button toggles `Net.request_lobby_ready(on)`; the host (`Game.on_lobby_ready_request`) logs `lobby_ready {player, on}` and broadcasts `apply_lobby_ready(peers)` into `Game.lobby_ready`. A joiner sends `false` on entering to receive everyone's marks. The host's button "Start the season" is enabled when `Game.all_ready()` (every other human ready; bots count as ready); Enter presses it. `lobby_ready` clears at match start, on `apply_match_start` and on leave.
- Pause menu: "Start match" removed, title "The lobby", no mouse capture on close while in the lobby.
- Voice in the lobby: `Players` is a stub (`lobby.gd` class `Voices`): an AudioListener3D and one bare Node3D per peer, so `Voice` still attaches emitters. Lobby voice is unplaced.
- QA args: `--lobby-ready` (client presses Ready after 1 s; host presses Start once a teammate is in and all are ready). `--lobby-start=<n>` and `--role=<id>` kept; `--lobby-start` bypasses Ready.
- Doc 05 s16 updated (menus, flow, pause menu, debug args).
