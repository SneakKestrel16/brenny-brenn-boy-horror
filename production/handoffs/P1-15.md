# P1-15: Move ENet host/join, roster, handshake and apply_clock into Net
Owner: Network & Voice  Date: 2026-10-07

## Done
- New autoload `Net` (`game/net/net.gd`), listed 4th in `project.godot` (Log, Data, Settings, Net, Clock, Game; doc 05 section 3).
- `Net` now owns: `host(port)` (port 45120, retries up to 45124, `max_channels` left 0 per doc 06 section 2), `join(ip[:port])` (raw IP only, D-024), the 10 s no-session_state error, the multiplayer signal handlers, the host-side join handshake (session_state, roster, clock to the joiner) and roster rebroadcast on leave, and the three RPCs `apply_session_state`, `apply_roster`, `apply_clock`.
- `Net.to_peers(method, args, targets = [])`: the one channel-0 send path (doc 06 section 14). It is a no-op without a peer or with no connected peers. `Clock._broadcast` uses it.
- `server_relay = false` is set when the peer is created (doc 06 section 2, D-010). This is the only behaviour change; current traffic is all host-originated, so it changes nothing observable.
- Minimal `game/core/` edits (Gameplay's files, done as the task asked): `Game` lost its ENet code, constants and signal handlers. `Game.start_host` calls `Net.host` and still owns the session id, `Log.open`, `session_start` and `Clock.start`. `Game.apply_session_state`/`apply_roster` and `Clock.apply_clock` are plain functions now; `Net`'s RPCs call them. `Game.players`, `player_joined`/`player_left`, `in_session` stay in `Game`; `Net` writes them on connect and disconnect, in the same order as before.
